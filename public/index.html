Red flag analysis

What gave it away?

Review the clues before marking the module complete.

🌐
Suspicious domain
The real destination should be the organization's known domain. Here, the registrable domain is a look-alike training domain, not the expected provider.
🔓
Insecure scheme
The page uses HTTP and an unlocked icon. Sensitive sign-ins should use HTTPS and still require domain verification.
🔤
Subdomain spoofing
Attackers place trusted words at the beginning of a URL. Focus on the registrable domain immediately before the public suffix.
🛡️
Defensive habit
Use a password manager and phishing-resistant MFA. Password managers usually refuse to fill credentials on the wrong domain.

🚩 Vague threat: Real alerts usually include useful context like time, device, and location.
🚩 Urgency and fear: Threats and tight deadlines are common social-engineering triggers.
🚩 Suspicious link: Navigate directly to the known site instead of clicking email links.
🚩 Deceptive CTA: Buttons can display trusted text while pointing somewhere else.
🚩 Fake authority: A signature block is easy to forge. Validate headers, domains, and context.
